# Roster outlook usability and performance — v1.5.1

## Agreed behavior

- Show every existing starter, academy player and FA, including rookies. Mark a current-year rookie only when recorded `debutYear` matches the franchise year; do not guess from age or missing metadata. The user clarified that existing rookies remain eligible for moves. Future rookies generated inside scenarios never become forecast rows. Preserve all real roster-market rules and replacement candidates.
- Give every player-search field in Live and Hall/Season History an explicit X that clears only its query and returns focus to the input. Preserve active filters, selected entities and existing Escape/close behavior.
- Integrate the outlook section with the season's compact bordered panels, typography, role/region/team artwork and roster-status badges. Display main/academy/FA badges beside current seats and sampled destinations; a destination does not need a rookie badge.
- Let Stay, Other team, To academy, To main roster and Become FA table headers toggle descending/ascending ordering with a visible direction and `aria-sort`. Keep the order dropdown synchronized, including Stay.
- Make Reset outlook filters a real styled button. Explain each player's observed outcomes, relevant performance/role gap, demotion rules and manual decisions clearly without presenting sample frequencies as certainty or claiming unmeasured causal contributions. Give destination percentages space beside the scrollbar.

## Implementation sequence

1. **Measure and share forecast work.** Record a repeatable baseline using a disposable synthetic season. Update `lib/season/rosterOutlook.ts`, `lib/season/rosterOutlookView.ts`, `lib/sim/rosterOutlook.worker.ts` and the split-checkpoint helper in `lib/season/franchise.ts`. Reuse the already evaluated split outcomes across unchanged scenarios; keep scenario RNG and market behavior identical. Expose real scenario-count progress in batches while keeping the synchronous domain API for tests. Never lower the sample count to claim a speedup.
2. **Cache and loading experience.** Add a scoped forecast hook in `components/season/` that retains only the latest completed input/result, reuses it on reopen, and invalidates on a changed season or champion catalogue. Cancel obsolete workers and reject stale responses. Keep expensive work behind expansion. Replace bare loading text with a season-themed progress indicator and skeleton, respecting reduced motion and keeping filters usable. No persistence/schema changes.
3. **Rookie identity and explanation model.** Keep existing rookies in the output, show a Rookie badge beside their current seat (not sampled destinations), and produce outcome-specific explanatory text from known inputs and sampled counts. Extend `lib/season/rosterOutlook.test.ts` for rookie visibility, year boundaries, unknown debut metadata, deterministic results and progress parity.
4. **Player search clearing.** Add a reusable clearable search component and use it in `components/season/LivePlayerSearch.tsx`, `components/SeasonHistoryView.tsx`, `components/hall/ComparePanel.tsx`, `components/hall/TitlePlayground.tsx`, `components/hall/MarketHistoryPanel.tsx` and outlook. Preserve each input's labeling and sizing. Avoid duplicate native cancel controls.
5. **Outlook presentation.** Refine `components/season/RosterOutlookPanel.tsx` with season-style section header, compact window context, status badges, sorting headers, reset button, clearer explanation hierarchy and padded destination scrolling. Reuse existing palette and assets; no new dependencies or external visual redesign.
6. **Verify and capture.** Extend relevant Playwright tests for clear/focus, sorting both directions, rookie visibility/year changes, loading/progress, retry, reopening cache, recalculation and minimum 1024px width. Inspect screenshots at desktop sizes. Compare forecast timing on the same fixture. Run unit tests, lint, types, release/dependency checks, full browser suite, native tests and desktop bundles as appropriate.
7. **Publish.** Synchronize all application metadata to 1.5.1 with the existing version script. Commit scoped changes and captures using conventional commits and the configured Git identity, with no coauthor/AI attribution. Check remote state, atomically push `main` and `v1.5.1`, then verify successful CI and both public release assets. Preserve unrelated `training/` data.

## Acceptance and safety

No live rosters, RNG streams, saves or historical records are modified by opening outlook. Cache reuse never presents a forecast for a different snapshot. Loading progress reports work actually completed. Search X buttons remain keyboard accessible and do not close their parent panel. User-facing copy stays in English. Screenshots and benchmark/check results will be recorded after implementation; planned checks are not reported as completed.


## Implementation and verification record

- Implemented all agreed behavior. Current-year rookies remain in main/academy/FA rows and can move normally. The Rookie badge uses explicit debut metadata only. Shared status badges are used in current seats and destinations, with no Rookie destination badge.
- Kept all 160 scenarios. A synthetic split snapshot with 60 teams, 300 players and 1,200 recorded games measured 157 ms median before and 108 ms after (five runs after an eight-sample warmup, about 31% less compute time on this machine). Scenario counts and destinations matched after normalizing fixture timestamp-based team IDs. This is a local synthetic benchmark, not a guarantee for every save or window.
- Added regressions for real progress and unchanged generator results, existing rookies, debut-year boundaries, and guarded checkpoint reuse. Browser coverage includes all probability headers in both directions, filter/dropdown agreement, clear/focus behavior across Live and Hall, completed-cache reuse, invalidation after Proceed, failure/retry, minimum width and padded destinations.
- Local checks passed: 131 unit files / 1,511 tests, full lint, typecheck, 14 release/version tests, dependency audit and 12 native Rust tests. The production dependency audit is clean; the existing documented development-only exceptions remain unchanged.
- Local Tauri 1.5.1 build generated app.exe and both Windows x64 installers. Browser verification uses the production export in Edge. Native tests cover commands/storage; no personal installation or AppData was used for an interactive native test. Release CI performs its own disposable Windows install/reopen/upgrade smoke.
- Historical captures were removed during repository cleanup. Current outlook and search tests regenerate them in the ignored `test-results/playwright/roster-outlook/` directory. The 80/160 loading capture deliberately holds a fixture worker at that progress point; actual progress emission is covered by the generator regression.
- Full browser suite: 110 tests passed in Edge (3.2 minutes). Updated legacy selectors to account for the clear-button input wrapper.
- Release target: v1.5.1. Publication is gated by the repository Windows release workflow, including interface checks, native checks, and disposable install/upgrade/reopen smoke. The final workflow status and installers are available on the GitHub release and Actions pages.
